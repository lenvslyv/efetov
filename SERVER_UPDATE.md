# Обновление Sechenov Scientific

После доработок запускайте в PowerShell на своём компьютере один и тот же блок:

```powershell
cd C:\SECHENOV\efetov\efetov
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\update-server.ps1
```

Сценарий устанавливает frontend-зависимости из package-lock.json, собирает интерфейс, запускает тесты на отдельной базе и создаёт новый архив. Затем он загружает архив и соответствующий ему установщик на сервер по SSH. Подтверждение sudo, если оно потребуется, вводится в терминале; пароль при вводе не отображается.

На сервере проверяются содержимое пакета, зависимости и импорт приложения. Пока эти проверки не пройдены, работающая служба не останавливается. После этого сохраняются копии кода, базы с WAL, загруженных файлов и конфигурации; приложение обновляется и запускается. Корневая папка приложения сохраняет владельца и права доступа.

Успешное завершение обозначается строкой `UPDATE OK` и строкой `Release: ss-...`. Установщик проверяет доступность API, номер сборки и контрольную сумму HTML, полученного от сервера. После успеха откройте https://trial-test.sechenov.ai и нажмите **Ctrl+F5**.

Во время резервного копирования и установки приложение временно недоступно. Место резервной копии выводится в терминале: `/var/backups/efetov/update-...`. Копии автоматически не удаляются.

При неудачной проверке после установки сценарий возвращает предыдущий код, восстанавливает права рабочей папки и проверяет запуск. `ROLLBACK OK` означает, что предыдущая версия снова отвечает; это не означает успешную установку новой версии. При `ROLLBACK FAILED` выводятся состояние службы и последние записи журнала.

## Проверка пакета без установки

```powershell
cd C:\SECHENOV\efetov\efetov
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\update-server.ps1 -PrepareOnly
```

Будут выполнены сборка и тесты, но отправки файлов и изменений на сервере не будет.

## Если возникла ошибка

```powershell
ssh.exe -t -p 8539 -i ".ssh\id_ed25519" vasilyeva@178.185.223.91 "sudo systemctl status efetov --no-pager -l; sudo journalctl -u efetov -n 40 --no-pager"
```

Не считайте установку успешной по одному только статусу `active`: процесс может завершиться сразу после старта. Ориентируйтесь на `UPDATE OK` после проверки HTTP и версии.

## Границы применения

Этот сценарий подходит для обычных доработок текущего проекта. При изменении Python-зависимостей он остановится до изменения сервера и покажет разницу. Новые зависимости, изменение конфигурации, системных библиотек или несовместимые миграции БД требуют отдельного плана установки. Автоматический откат кода не отменяет уже выполненные изменения структуры БД.

Архив содержит исходники и собранный интерфейс. В него не включаются локальная база, загруженные пользователями файлы, SSH-ключи, виртуальное окружение Python и файл настроек сервера. Незакоммиченные доработки тоже включаются: устанавливается содержимое локальной папки на момент запуска.
