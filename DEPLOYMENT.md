## Проверка и обслуживание

На сервере:

```bash
sudo systemctl status efetov --no-pager
sudo journalctl -u efetov -n 100 --no-pager
curl -fsS http://127.0.0.1:8000/api/health
curl -fsS -H 'Host: trial-test.sechenov.ai' http://127.0.0.1/api/health
sudo systemctl restart efetov
```

Перед обновлением нужно сохранить согласованную резервную копию SQLite и вложений. Обновления устанавливать в новую папку версии, собирать интерфейс и проверять на временной базе, затем менять путь в конфигурации службы. Существующий `/var/lib/efetov` сохранять; локальную базу разработчика поверх него не переносить. Не вызывать `/api/reset-demo` при обновлении.

Для отката к сохранённой установке необходимо остановить службу, восстановить данные и конфигурацию из резервной копии и исправить старый адрес привязки `172.16.0.19`: он больше не принадлежит серверу. Возвращение старой конфигурации без исправления адреса приведёт к исходному сбою запуска. Восстановление данных из резервной копии удалит изменения, внесённые после неё.
